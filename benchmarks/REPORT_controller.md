## How to read this

- *frame* = main-thread cost of `CharacterController.update` per 60 Hz tick (generation runs on a worker thread unless *sync*). *FPS capacity* = 1000 / frame time: how fast the animation layer alone could tick.
- *body t90* = seconds from an input change until the rendered hips reach 90 % of the commanded velocity change; *gameplay t90* is the same for the simulated gameplay trajectory (spring-damper). Both use the same 0.25 s smoothing filter, so their difference is the animation lag.
- *tracking err* = mean ground distance between rendered hips and the gameplay trajectory.
- *foot slide* = horizontal foot speed while planted (height + speed contact heuristic, 60 Hz).
- *pop p99* = 99th-percentile joint acceleration / median (spikes = visible pops).
- *late* = results that arrived after their switch frame (hidden by inertialization).
- Generation latency is higher than the isolated model benchmark because the worker shares 4 vCPUs with the game loop (1 core reserved).
